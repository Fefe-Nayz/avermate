Audit & roadmap — 14 août 2026

Avermate × Fichr

La thèse produit : une alternative open source à NotebookLM fusionnée avec le suivi de notes, dans l'esprit agrégateur de Papillon — sources de cours multi-types (PDF, liens, texte, audio) synchronisées depuis Moodle et consorts, agenda/kanban, fiches, copies scannées, enregistrements — le tout lisible par n'importe quel agent IA via le MCP existant.

Repo avermate, branche rewrite @ 46c966b Sources auditées avermate · Fichr · CoursePilot · « Math-M. Coutens » Méthode 4 audits parallèles, findings re-vérifiés en lecture directe
  • La vision est réalisable dans l'année, et le socle est meilleur que prévu : l'architecture d'avermate rewrite est explicitement accueillante pour de nouveaux domaines (routeurs uniformes, ownership centralisé, MCP qui délègue à l'oRPC, primitives réutilisables).
  • Trois fondations manquent et bloquent presque tout le reste : une entité fichier générique, une infra de tâches asynchrones, et un découpage du serveur MCP (2 160 lignes) avant d'y ajouter ~40 outils.
  • Les trois « essais fishr » sont en réalité une seule lignée, et l'essentiel de sa valeur est un prototype supprimé qui survit dans l'historique git de Fichr (commit b8c5714) : à miner pour le design, pas à porter.
  • Le « scraper » Moodle n'en est pas un : c'est un client REST propre de l'API Web Services (~250 lignes à porter en TypeScript). La feature « plus jamais toucher au site de la prépa » est peu coûteuse.
  • 20 plans d'implémentation exécutables sont écrits dans plans/ : fondations (000–003), premières features (004–006), vague 2 (007–013 : ADR IA, sync providers, OCR, fiches, autorage MCP, enregistrement, sources multi-types), transversaux TODO.md (014–016), et extensions (017 outputs studio — cartes mentales/slides/PPTX, 018 spike Pronote/EcoleDirecte, 019 modèle de soutenabilité BYOK/satellite/self-host). L'index contient une carte de couverture de la vision et une section « Future » explicite.

01 — L'existant

Avermate rewrite : un socle rigoureux, trois angles morts

La matrice de parité main → rewrite est entièrement « Implemented », les invariants de domaine sont documentés, la CI fait tourner format, lint, types, migrations, tests et builds. Côté extension, tout est en place : un domaine nouveau = 1 fichier de schéma + 1 routeur copié sur goals.ts + 1 ligne d'enregistrement + 1 scope MCP. Le MCP délègue intégralement aux procédures oRPC (une seule source de vérité pour ownership et validation), avec confirmation multi-tour + clé d'idempotence pour le destructif — un primitif directement réutilisable pour « supprimer un dossier de cours ».

Atout

Ledger d'idempotence prouvé

yearSetupRequests (unique userId + idempotencyKey) est le gabarit exact pour dédupliquer syncs Moodle et jobs OCR.

Atout

Modèle de document déjà résolu

dashboardCards : JSON typé + version + table miroir relationnelle. C'est la réponse maison pour stocker fiches et transcripts proprement.

Atout

Navigation déclarée une fois

nav.ts alimente sidebar, tab bar, breadcrumb et palette : un espace « Cours » ou « Agenda » apparaît partout en une entrée.

Blocage

Aucune tâche asynchrone

Pas de queue, pas de cron, pas de worker. OCR et transcription (plusieurs minutes) n'ont nulle part où tourner. C'est LE chemin critique.

Blocage

Aucune entité fichier

Deux colonnes URL ad hoc (avatar, screenshot de feedback), limite 2 Mo, clé de stockage re-parsée par regex. Rien ne sait qu'un fichier existe.

Blocage

Aucune recherche

Ni FTS5 ni vecteurs nulle part. « Browsable par les agents » et « retrouver un passage de cours » partent de zéro.

Angles morts secondaires confirmés : deux vérifications admin divergentes (isAdmin vs role.split(",") dans le MCP), micro mobile explicitement désactivé (app.json), docs sociales décrivant un modèle de privacy supprimé, quick-add mobile jamais branché.

Conclusion nette : rien du TypeScript de Fichr n'est à reprendre (avermate a la même stack, en mieux). La valeur est dans le prototype Python supprimé, récupérable via git show b8c5714 : le modèle de données prouvé (cours → fichiers sources → markdown OCR mirroré → projets de fiches), le schéma de messages de chat avec branches (parent_message_id, branch_index, client_message_id — coûteux à retrofitter, gratuit à prévoir), le catalogue de 12 outils agent validé à l'usage, et les gabarits LaTeX de fiches CPGE (BoxDef/BoxThm/BoxMeth/BoxPit).

Trois points de sécurité à traiter côté prototypes (hors repo avermate) :

① webapp/data/chats.db — 94 Ko de vraies conversations — est commité et poussé sur Fichr@prototype : à purger avant toute publication du repo. ② Le dernier commit désactive la vérification TLS du client Moodle (verify=False) : le token a transité en clair vis-à-vis d'un attaquant actif — réactiver la vérification puis régénérer le token. ③ L'outil execute_command du chat exécutait shell=True avec une denylist de 4 chaînes et une « approbation » purement décorative : ne jamais porter tel quel (le plan de la roadmap l'exclut explicitement).

05 — Plans écrits

Vingt plans exécutables dans plans/

Chaque plan est auto-portant (contexte inliné, étapes vérifiables commande par commande, bornes strictes, conditions d'arrêt), pensé pour être exécuté par un agent sans aucun contexte de cette session. Ordre recommandé :

  1. 000 — Hygiène pré-fusion S docs sociales/charts corrigées, switch mort supprimé, composants mobiles morts retirés.
  2. 001 — Entité files + module storage partagé M la fondation de cours, copies et audio ; migre avatar et feedback.
  3. 002 — Substrat de jobs durable L table + runner in-process à bail + routeur de statut ; premiers consommateurs : purge feedback, reaper MCP.
  4. 003 — MCP modulaire + check admin unifié M un module par surface, registre ordonné, harness de conformité comme filet.
  5. 004 — Domaine agenda/todo/kanban L planner_items avec statut todo/doing/done, flux agrégé (goals, notes, périodes), 3 vues (calendrier, liste, board dnd-kit) + scopes MCP.
  6. 005 — Tranche verticale « cours » L sources multi-types (fichier / lien / texte collé), spike proxy-vs-presign, arborescence sur files, outils MCP en lecture.
  7. 006 — Copies attachées aux notes S–M la première victoire visible de l'infra fichiers.
  8. 007 — ADR architecture IA S–M MCP-first (pas d'agent embarqué en vague 2), tools + prompts plutôt que « skills », clés opérateur puis BYOK, spec du schéma de chat à branches pour plus tard.
  9. 008 — Framework sync providers + connecteur Moodle L interface à capacités (files, puis devoirs/EDT/notes à la Pronote), port TS du client WS, credentials scellés AES-GCM, TLS vérifié.
  10. 009 — Pipeline OCR Mistral M–L artifacts markdown par document, job idempotent, plafond de pages, skip_patterns enfin honoré, dry-run chiffré.
  11. 010 — Domaine fiches/documents + éditeur L CodeMirror + preview KaTeX, callouts CPGE [!DEF]/[!THM]/[!METH]/[!PIEGE]/[!CHECK], révisions optimistes, export impression A4.
  12. 011 — Surface MCP d'autorage + prompts M outils documents.* révision-fencés + prompts fiche-methodology et fiche-from-chapter — « rédiger via n'importe quel agent ».
  13. 012 — Enregistrement + transcription des cours XL segmentation à la capture (10 min), vague permissions micro + prebuild, jobs de transcription derrière un seam provider (Mistral/OpenAI), transcript horodaté.
  14. 013 — Ingestion des sources non-fichiers M liens web → markdown lisible (Readability + turndown), garde SSRF stricte, branche PDF-en-ligne → OCR ; YouTube en roadmap.
  15. 014 — Typo fluide tailwind-clamp S–M le choix issu de TODO.md, appliqué aux surfaces expressives uniquement.
  16. 015 — Galerie de cards préconfigurées M–L catalogue admin-curé, preview LIVE sur ses propres données, installation via le cards.create existant.
  17. 016 — Design system cross-platform L tokens partagés dans @avermate/core, adaptateurs web/mobile, densité desktop via pointer: fine.
  18. 017 — Outputs studio : cartes mentales + slides L deux kinds structurés validés côté serveur, éditeur outline + canvas xyflow, mode présentation, export .pptx réel (pptxgenjs en job) ; podcasts/vidéos réservés (coût = 019).
  19. 018 — Spike connecteurs Pronote / EcoleDirecte / Skolengo M évaluation sourcée de l'écosystème Papillon (pawnote…), verdicts par capacité (devoirs/EDT/notes), prototype lecture seule flag-gaté si GO.
  20. 019 — Modèle de soutenabilité M ADR gratuit + open source : cœur gratuit à vie, BYOK par utilisateur (clés scellées), protocole « satellite » self-host pour stockage/inférence (design), doc self-hosting complète, tier payant en dernier recours.

06 — Séquencement proposé

Une année réaliste

  • Rentrée → Toussaint : fondations (000–003) en parallèle + l'ADR IA (007, une après-midi), puis l'agenda/kanban (004) comme premier incrément visible — il n'attend ni fichiers ni jobs.
  • Toussaint → Noël : l'espace cours multi-sources (005) + copies (006), puis le connecteur Moodle (008) — à ce stade « plus jamais le site de la prépa » est tenu.
  • Hiver : OCR (009) + liens web (013) puis la recherche FTS sur le corpus markdown ; l'app devient interrogeable par les agents MCP sur le contenu des cours.
  • Printemps : fiches + éditeur (010) puis la surface d'autorage MCP et ses prompts (011) — rédiger des fiches via n'importe quel agent, sans agent embarqué à héberger.
  • Été : enregistrement + transcription (012, vague permissions/prebuild groupée avec le scan caméra), embeddings si le FTS ne suffit pas ; les transversaux (014–016) se glissent dans les creux, indépendants de tout.
